fst · 外链发射台 — 产品需求文档

面向独立 SEO 操作者的半自动化外链发布辅助工具：本地管理台 + 油猴脚本，主攻海外平台
版本 v0.1（评审稿） 日期 2026-10-15 状态：待评审 部署形态：本地单机
1. 背景与目标 2. 范围 3. 核心流程 4. 功能需求 5. 共享规则 6. 假设与待定项

1. 背景与目标

批量建设外链时，操作者需要在多个海外平台（Web2.0 博客、论坛、书签站）重复做同一套动作：打开站点 → 登录 → 新建帖子 → 手工粘贴标题、正文、锚文本 → 提交 → 再到表格里登记记录。其中绝大多数时间消耗在反复复制粘贴内容和整理记录上，而不是登录、验证码等必须人工处理的环节。

因此本产品将流程拆分为「机器负责的部分」与「人工负责的部分」：

  • 机器负责：维护文案模板并生成不重复变体、按平台规则把内容自动填充进发布表单、记录与状态管理、批量收录检测。
  • 人工负责：登录账号、通过验证码、最终检查并点击提交（产品不自动提交）、处理异常。

预期可观察的结果：操作者在目标平台页面上，从打开新建页到完成提交，只需要人工执行「登录、过验证码、检查、点击提交」四步；每条外链从任务创建到收录状态，全程在管理台中可查。

3. 核心流程

一次完整的外链发布旅程如下，蓝色为机器自动环节，其余为人工环节：

① 管理台创建任务
目标URL+锚文本+模板→ ② 人工登录目标平台
进入发帖页→ ③ 脚本匹配平台规则
悬浮面板出现→ ④ 拉取待发任务
取定变体内容→ ⑤ 一键填充表单→ ⑥ 人工检查内容
过验证码→ ⑦ 人工点击提交→ ⑧ 回填落地 URL
状态→已发布→ ⑨ 批量收录检测

恢复路径：发布失败（如被删帖、封号、内容被拒）时，任务标记为「失败」并可一键重置回「待发」，重新生成变体或换平台再发。

4. 功能需求

FR-01 外链任务管理

目的：管理台的主界面，承载所有待发/已发外链，是其余功能的操作入口。

触发：用户打开管理台首页。

处理规则：

  • 创建任务必填「目标 URL」与「锚文本」；可选关联一个文案模板（不关联时使用默认通用模板）。
  • 目标 URL 校验：必须以 http:// 或 https:// 开头；锚文本非空且长度 ≤ 100 字符。
  • 任务创建后进入「待发」状态，出现在列表顶部；不支持创建时直接指定状态。
  • 列表支持按状态筛选（待发 / 已发布 / 失败 / 已收录 / 未收录 / 未确认）和按关键字搜索（锚文本、URL）。
  • 删除需二次确认；已发布的任务删除时提示「该任务的发布记录将一并删除」。
字段必填说明
目标 URL是要推广的页面链接，即锚文本指向的地址
锚文本是外链锚文字，模板中的 {锚文本} 变量取此值
关联模板否默认使用通用模板
平台否发布后由脚本自动识别回填，也可手动指定
状态系统见共享规则中的状态机
落地 URL发布后发出去的帖子/文章的实际链接
时间戳系统创建时间、发布时间、检测时间

异常：URL 格式非法或锚文本为空时阻止创建并给出行内错误提示；列表为空时展示引导文案「还没有任务，点击右上角新建第一条外链任务」。

FR-02 文案模板库与变体生成

目的：避免多个平台发布完全相同的文案（重复内容风险），把「写一次」变成「配一次模板」。

触发：用户在「文案模板」页创建/编辑模板；脚本拉取任务时取定变体。

处理规则：

  • 模板由「标题模板」与「正文模板」两部分组成，均支持 Spin 语法与变量占位（语法见共享规则）。
  • 编辑时实时预览：点击「生成变体」可反复预览不同变体效果。
  • 变体取定规则（关键）：任务第一次被脚本填充时生成并保存固定变体，之后该任务无论填充多少次都使用同一份内容；仅当任务被重置为「待发」并选择「换内容」时才重新生成。
  • 变体查重：同一模板近期（最近 20 次）生成过的变体不再分配给新任务；若模板组合空间过小导致无法查重，给出提示「该模板变化组合不足，建议增加可选词」。
  • 模板可删除；被任务引用的模板删除时提示「仍有 N 个任务引用此模板，删除后这些任务将回退到通用模板」。

异常：模板 Spin 语法错误（如括号不配对）时，保存被阻止并标出出错位置。

FR-03 平台规则库

目的：让脚本知道「当前网站上，标题/正文/链接该填进哪些输入框」。

处理规则：

  • 一条规则 = 平台名称 + 域名匹配（支持精确域名与通配符，如 *.wordpress.com）+ 字段映射（标题、正文、链接 URL、标签四个槽位，各槽位填写 CSS 选择器）。
  • 内置若干常见海外平台示例规则（如 Blogger、Medium、WordPress.com、Diigo 等通用 Web2.0 / 书签站）[Assumption, TBD：首批内置清单]。
  • 用户可在管理台添加、修改、停用自定义规则；添加时提供「在目标页面上点选元素生成选择器」的辅助模式（脚本端辅助拾取），降低配置门槛。
  • 一个域名命中多条规则时，取最近更新且未停用的一条；规则停用后该域名视作未匹配。

异常：页面上按选择器找不到字段时，悬浮面板显示「部分字段未找到，请手动粘贴」并退化为一键复制模式。

FR-04 油猴脚本（浏览器端助手）

目的：在目标平台页面上完成内容自动填充与状态回写，是「半自动」的执行端。

触发：脚本随所有网页加载，仅当当前域名命中平台规则库时激活。

处理规则：

  • 激活后在页面右下角显示悬浮面板：平台名称、当前任务卡片（锚文本 + 变体预览）、操作按钮。
  • 「拉取下一个任务」：从管理台取一条「待发」任务（优先取手动指定了当前平台者），并在取定瞬间生成固定变体。
  • 「一键填充」：按规则将标题模板渲染结果填入标题框、正文模板渲染结果（含 {锚文本} 超链接的 HTML）填入正文编辑器；若正文编辑器是富文本，优先写入 HTML，失败则降级为纯文本 + 复制兜底。
  • 填充后面板显示「已填充，请人工检查后提交」；用户自行完成验证码与提交。
  • 提交成功后用户点击面板「标记已发布」，粘贴落地 URL（或由脚本尝试从地址栏预填），任务状态更新为「已发布」。
  • 与脚本无法连通管理台时（管理台未启动），面板显示离线提示，并提供「复制当前任务内容」的手动兜底。

异常与空状态：无待发任务时面板显示「队列为空」；域名未命中规则时面板不出现（或仅显示一个可手动唤起的小图标）。

FR-05 发布记录与状态追踪

目的：让操作者随时掌握每条外链发到哪、发了什么、状态如何。

处理规则：

  • 任务列表即发布记录：每行展示锚文本、目标 URL、平台、状态、落地 URL、发布时间。
  • 状态流转遵循共享规则中的状态机；「已发布」必须填写落地 URL 后才可确认（落地 URL 需以 http(s):// 开头）。
  • 「失败」任务支持两个动作：重置为待发（可同时勾选「换内容」重新生成变体）与直接删除。
  • 平台、发布时间由脚本回写；落地 URL 支持脚本预填 + 人工修改。

状态机（canonical）

状态含义与允许操作

状态含义允许的操作
待发已创建，尚未发布编辑、删除、拉取填充

FR-06 收录检测

目的：回答「发出去的链接到底有没有被搜索引擎收录」。

触发：用户在列表中勾选一条或多条「已发布」任务，点击「检测收录」。

处理规则：

  • 自动检测：管理台逐条向 Bing 发起 url: / 站内查询，判定落地 URL 是否出现在结果中；逐条间隔 2–5 秒随机延时，避免高频请求。
  • 结果三态：出现在结果中 → 已收录；确认无结果 → 未收录；请求失败、结果页异常（验证码/反爬拦截）→ 未确认。
  • 「未确认」任务每条附「打开检测页」按钮（生成 Google 站内查询链接），由人工在浏览器确认后手动标记为已收录/未收录。
  • 同一任务两次检测间隔 ≥ 10 分钟，避免无意义重复请求；检测历史（时间+结果）保留最近 3 次供对比。

异常：批量检测进行中时按钮变为「检测中… (n/m)」，可随时中止；中止不产生状态变更。

可靠性说明 [Assumption, TBD]：服务端自动检测依赖搜索引擎的反爬策略，可能经常落入「未确认」，人工复核兜底是正式流程的一部分，不是异常。

5. 共享规则

5.1 半自动边界（canonical）

  • 脚本只做：读规则、取任务、生成变体、填充字段、复制兜底、回写状态。不做：点击提交、处理验证码、模拟登录、绕过风控。
  • 所有涉及对外发布的关键动作（提交）由用户在目标网站上亲手完成。

5.2 Spin 语法与变量（canonical）

  • {选项A|选项B|选项C}：随机选择其一，支持嵌套一层（如 {a|{b|c}}），嵌套超过一层按文本处理并提示。
  • 变量占位：{锚文本}、{目标URL}、{日期}（YYYY-MM-DD）。正文中的锚文本链接渲染为 <a href="目标URL">锚文本</a>。
  • 括号不配对视为语法错误，阻止保存/取定。

5.3 状态机（canonical）

唯一状态机见 FR-05 图与表；其他章节引用状态名时以此为准，不得出现平行定义。核心约束：「已发布」的前置条件是落地 URL 有效；「失败」不可直接跳到「已发布」，必须先重置为「待发」。

5.4 数据与隐私边界

  • 所有数据（任务、模板、规则、记录）仅存储在本机；脚本仅与本机管理台通信，不向任何远程服务器上传数据。
  • 工具不托管、不加密存储第三方账号密码（本版不含账号管理模块）。
